## ABL kernel handoff analysis

Status: **COMPLETE**

The outer `abl.elf` is an ELF32 ARM container whose load segment contains a compressed UEFI firmware volume. Decompressing that volume exposes the `LinuxLoader` application as a stripped AArch64 PE32+ image.

The DZG1 `LinuxLoader` computes the ARM64 load base at RVA `0x176f8` through `0x17740`. Its selected ARM64 load constants are `0x00080000` and `0x05600000`. The entry calculation at RVA `0x178cc` through `0x178f0` adds the raw Image `text_offset`. The final ARM64 handoff loads the entry at RVA `0x18d48` and branches through it at RVA `0x18da4`. All 22 vendor-boot DTBs independently contain `gunyah_hyp_region@80000000` with `reg = <0 0x80000000 0 0x00e00000>`.

Therefore the values for this target are:

```c
#define P0_PHYS_OFFSET      0x80000000ULL
#define P0_KERNEL_PHYS_LOAD 0x80080000ULL
```

`P0_ORACLE_PROBE_OFFSET 0x1f0000` (32 rows, 256 source qwords, all verified

### Regression fix (2026-08)

The refactor commit `bebcae7` rewrote `target.h` as a standalone header and
accidentally dropped the device-verified geometry that commit `a8268ca` had
added on top of the DZF2 include: `MM_STRUCT_SZ 0x400` (the real DZG1
`mm_struct` slab object size, 1024 bytes, measured from `/proc/slabinfo`),
`KSNITCH_COLLISIONS 5`, and the inherited `SKB_DATA_DELTA -0x1000` /
`SLIDE_PSELECT_WORD_SHIFT 3` values of the identical 6.1.145 E3Q kernel.
With the common.h defaults (`0x500` / 4 / `-0xe80` / 0) the payload failed
on hardware at the KernelSnitch `sk_buff`/`mm_struct` leak stage
(`pipe KernelSnitch sk_buff page leak failed`,
`KernelSnitch mm_struct leak failed`, app killed with status 137). The
values above restore the a8268ca device-verified configuration.
